# Assignment 1 reflection

My breakthrough was realising that a plausible agent result is not evidence. I needed to design evidence that could prove it wrong.

The first simulation already moved when I dragged the slider and all of its original checks passed. It also produced a green sky and, at high elevation, a blue-looking Sun. My first instinct was to ask for more realistic colours. That would only have made the same unsupported model prettier. Instead, I paused implementation, separated the physics research from the coding pass, and made the assumptions explicit. The air-mass test used an independently written Kasten-Young reference, while relationship tests checked that the route grows continuously toward the horizon and that shorter wavelengths are removed more strongly. Those checks could reject an attractive but physically inconsistent result.

The same idea changed two later decisions. When repeated responsive patches kept passing narrow overflow checks but still looked broken, I stopped requesting another CSS adjustment. I changed the acceptance contract, discarded the overlay architecture and rebuilt the scene around one bounded SVG coordinate system. For the privacy coda, I defined forbidden capabilities before implementation, then used negative tests to prove the page did not request sensitive permissions, persist a fingerprint or send observations away.

This changed what I think directing an agent means. Higher-effort models, research passes and reviewers helped, but they were not the control system. The control system was the evidence around them: a plan that fixed scope, tests that did not share every assumption with the implementation, fresh-context review, real-browser checks, and explicit capability boundaries. I want to become a developer who makes a wrong answer cheap to reject, instead of becoming better at explaining why a convincing answer should be accepted.
