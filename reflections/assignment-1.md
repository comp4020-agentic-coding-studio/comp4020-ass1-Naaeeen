# Assignment 1 reflection

The page passed its checks and still showed a green sky. That was the moment I realised a test-green result can still be untrustworthy: I had asked the agent questions that were too weak to expose its mistake.

My first instinct was to tell the implementation agent to “make the colours more realistic.” Instead, I stopped the retry loop and separated the roles. A research subagent had a bounded brief: use primary sources, make assumptions explicit, and leave gaps unresolved rather than inventing an answer. A separate test-first pass then translated that research into an independently implemented Kasten-Young air-mass oracle plus relationship checks: lowering the Sun must increase air mass, reduce transmission, and remove blue faster than red. Only then could the implementation agent revise the model, and it was not allowed to weaken the tests. Browser reviewers answered a different question: did the rendered result actually look and behave coherently?

I reused that pattern when responsive patches kept passing overflow checks but still failed visually. Fresh-context reviewers compared alternative presentation architectures against the same viewport matrix. I rejected the passing HTML/CSS composition, changed the durable rules in `PLAN.md` and `CLAUDE.md`, and rebuilt the simulation around one bounded SVG coordinate system. Before adding the privacy reveal, a security review first defined capabilities the page must never use; negative tests turned those limits into executable constraints.

My breakthrough was therefore not finding a better prompt or model. It was learning to design an evaluation system in which research, generation, criticism and human judgement answer different questions. Stronger agents widened the solution space, but independent evidence decided what deserved acceptance. I now want to make a wrong answer cheap to reject—even when it is polished, test-green and confidently explained.
